#+TITLE: Celorga for Org mode users
#+DESCRIPTION: Org, rebuilt without Emacs: a portable Org runtime and CLI, and the Mac, iPhone, editor, and AI agent tools built on it.

Org mode got plain-text planning right: outlines, TODO states, schedules, properties, IDs, and links in files you own forever. But almost everything that truly understands an Org file still runs inside Emacs.

Celorga rebuilds the Org ecosystem without Emacs, with portability as the starting point. The parser, the semantics, and the command line form a standalone runtime that any app, editor, script, or agent can use. On top of it sit a native Mac app that combines an Org editor with an AI agent workspace, an iPhone app, VS Code and Vim support, and tools for the agents you already use.

Point it at your existing =~/org= folder. There is nothing to import or convert, and every file still opens in Emacs exactly as before.

* Why rebuild Org without Emacs?

Org the file format is useful far beyond Org the Emacs mode. Today, though, the ecosystem has a gap: there is no portable base to build on.

- *Org shouldn't require an editor.* A script, a CI job, a server, a phone app, or an AI agent that needs a real agenda, repeaters, or =:ID:= links has two options today: bundle a whole Emacs binary, or write another partial parser. Bundling Emacs is heavy, and starting Emacs just to answer an Org question adds startup time to every call.
- *Extending Org should build on tools you already have.* Emacs Lisp is powerful, but its libraries live inside Emacs. Celorga's runtime is TypeScript and installs with npm, on the Node.js toolchain most developer machines already have, and anything built on it can draw on the npm ecosystem. Plugins are ordinary programs that exchange JSON, so you can also write them in Python, Go, Rust, or shell and use those languages' libraries.
- *Every tool should agree on what a file means.* Most Org tools outside Emacs ship their own small parser that handles part of the format in its own way, so your agenda in one app doesn't quite match another. Celorga has one runtime that every client uses.

So Celorga decouples Org from Emacs completely. The format has a written specification and conformance fixtures, and the parser, semantics, CLI, and language server run without Emacs anywhere in the stack.

** What a portable base makes possible

Once Org no longer depends on an editor, the apps built on it don't have to stop where an editor does. Celorga for Mac puts your agenda and notes in a native window and lets coding agents and local models work on the same files, with citations and approvals. The iPhone app brings the same files to your phone.

None of these apps reimplements Org. The Mac app, the iPhone app, the VS Code extension, and the language server all use the same runtime and CLI that you can install with npm, so anything they do with your files, a script or a different app can do too.

* What Celorga is

- *A portable Org runtime.* One parser, one set of semantics, and one command line, with no Emacs dependency.
- *A native workspace.* A Mac app with an agenda, rendered and source editing, backlinks, a graph, meetings, data notebooks, and publishing, plus an iPhone app for capture, agenda, and approvals.
- *An agent control plane on plain text.* Claude Code, Codex, OpenCode, local models, and other agents read and cite your =.org= files, take on TODOs as work, and wait for your approval before anything consequential happens.

Celorga is free, open source under Apache-2.0, and needs no account. It is an independent project, not a fork of Org mode, and it is not affiliated with the GNU Org mode project.

* What feels familiar

If you know Org, you already know how to write for Celorga:

- Headlines, TODO keywords, priorities, tags, and your own TODO workflows.
- =SCHEDULED=, =DEADLINE=, =CLOSED=, repeaters, effort, clocks, and habits.
- Property drawers, =:ID:= links, and org-roam style notes, dailies, and backlinks.
- Lists, checkboxes and progress cookies, tables with =#+TBLFM:= formulas, and source blocks.
- Agenda files, capture, archive, and refile.

The files remain the source of truth. Celorga keeps no private database that you have to export from, and the agenda, backlinks, graph, and search are all built from the text. Notes that Celorga creates are ordinary =.org= files, so you can keep editing in Emacs and use Celorga beside it.

* What's new

** A polished app that isn't Emacs

Celorga for Mac is a native app with a real reading view. Open a note to read it rendered, or switch to source or split view to edit the text. The agenda, the backlinks for the current note, the graph, and fuzzy search all sit in one window. Prose mode gives you a calm writing surface where alternative phrasings, ghosted sentences, and cut passages stay recoverable in the file.

It is the Org experience for the times and people that Emacs doesn't reach: your laptop on the couch, a colleague who will never learn Emacs, or a day when you just want your agenda.

** Your Org files on your phone

The iPhone app reads the same synced folder. Capture a note, check the agenda, search everything, read rendered entries, and approve agent work from anywhere. Sync with iCloud, Git, Syncthing, or anything else that syncs a folder.

** Agents that work on your Org files

This is where Celorga goes well beyond any Org tool. Your notes become shared memory for every agent you use:

- *Bring the agents you already pay for.* Claude Code, Codex, OpenCode, Pi, OpenClaw, Ollama, and API providers all work, with no resold tokens.
- *Put several agents in one conversation.* Ask the same question of two agents, or let one hand work to another while you watch.
- *Turn a TODO into agent work.* Pick a heading, choose /Start work/, and the agent starts from the task and the notes behind it. The heading shows whether the agent is working, waiting on you, or done.
- *Cited answers.* Agents quote your notes with file and line references, so you can check every claim.
- *You approve what matters.* Edits are previewed as diffs, AI-written text stays marked until you accept it, and consequential steps wait in one approval queue on your Mac and phone.
- *Use any MCP client.* =celorga mcp serve= exposes your corpus to any MCP-compatible tool.

If you already ask agents to work on your Org files, Celorga gives them proper tooling, such as agenda queries, structured edits, link resolution, and validation, instead of leaving them to regex their way through your headlines.

** More from plain text

- *Data notebooks.* Run SQL over CSV, Parquet, DuckDB, or ClickHouse from a note, and keep the results and charts in the file.
- *Meetings.* Record and transcribe on your machine, then turn decisions into TODOs.
- *Publishing.* Turn a note into a web page, PDF, Beamer slides, or a Google Doc, with private details stripped first.
- *Encryption.* Encrypt one section to yourself, a device, or a single agent, and keep the rest of the file readable.

* The best foundation for Org outside Emacs

If you use Org outside Emacs, or want to build something on it, this is what the shared runtime gives you:

- *One interpretation everywhere.* The Mac app, the iPhone app, VS Code, Vim and Neovim, the CLI, and agents all use the same parser and semantics. A TODO, a repeater, or an =:ID:= link means the same thing in every client.
- *Plugins in any language.* Add commands, templates, and source-block renderers as Git packages that exchange JSON with Celorga, pinned to an exact commit in your corpus.
- *A strong VS Code extension.* It includes an agenda, TODO and planning commands, folding, backlinks, org-roam style dailies and ID links, formatting, and diagnostics, on macOS and Linux.
- *A language server for any editor.* The same diagnostics, navigation, and code actions are available in Vim, Neovim, Emacs, or anything else that speaks LSP.
- *A CLI that's built for scripts.* =celorga agenda=, =search=, =todo=, =lint=, and =publish= return JSON, and every change is a preview until you pass =--apply=.

Improvements to the runtime reach every client at once, so the experience keeps getting better everywhere instead of in one app at a time.

npm install -g celorga

celorga lint --dir ~/org --recursive

* Keep Emacs too

You don't have to choose. Celorga and Emacs read the same files, so many people keep Emacs as their editor and use Celorga for their phone, agenda, agents, and publishing.

Celorga covers the Org you use every day. It doesn't run Emacs Lisp, so custom agenda commands, Babel pipelines, and packages that depend on your =init.el= stay in Emacs. Celorga-specific additions are ordinary Org text, so Emacs shows them as normal text without breaking anything. For details, see [[file:semantics-status.org][Semantics and status]].

* Try it in five minutes

1. [[file:downloads.org][Download Celorga for Mac]], or run =npm install -g celorga= on macOS or Linux.
2. Open your existing Org folder. Your headings, TODOs, schedules, and links appear right away.
3. Open the agenda, then connect an agent you already use and ask it about your notes.

Questions, bug reports, and Org edge cases that Celorga gets wrong are very welcome on [[https://github.com/aviaviavi/celorga/issues][GitHub]].
