OpenClaw knowledge layer

Corpus layout, safe writes, and review-gated memory promotion

OpenClaw can use a Celorga corpus as a local-first knowledge layer: raw observations stay auditable, deterministic Celorga commands derive indexes and views, and AI or external integrations write reviewable artifacts before anything becomes durable memory.

This page is the integration contract. An OpenClaw integration should be able to implement the layout and safety rules here without reaching into Celorga internals.

Corpus zones

Use predictable top-level zones so humans, Celorga, and automation agree on what each file means:

ZoneExample pathsOwnerMeaning
raw/raw/meetings/2026-05-20-team-sync.transcript.org, raw/imports/slack/2026-05-20.jsoncapture/import toolsSource material and append-only observations. Prefer minimal rewriting.
notes/ and daily/daily/2026-05-20.org, notes/people/alex.org, notes/projects/openclaw.orghumans plus safe agent editsCanonical working notes, TODOs, durable memory, and curated entities.
compiled/compiled/corpus.json, compiled/team-sync-context.jsondeterministic Celorga commandsMachine artifacts derived from raw/ and notes/. Safe to regenerate.
views/views/meeting-summaries/2026-05-20-team-sync.org, views/link-suggestions.orgdeterministic reports or generated draftsReview surfaces, summaries, diagnostics, backlinks, and suggestions. Usually not canonical.
publish/publish/team-handbook/, publish/openclaw-memory.htmlpublish/export jobsShareable output created from reviewed source material.

Recommended placement:

  • Daily notes: daily/YYYY-MM-DD.org

  • Imported transcripts and logs: raw/<source>/YYYY-MM-DD-<slug>.<kind>.org or original machine format under raw/imports/

  • Generated summaries: views/<workflow>/<slug>.org with CELORGA_REVIEW_STATUS: review-required

  • Review artifacts and suggestion reports: views/review/<slug>.org or views/link-suggestions.org

  • Compiled query/context packets: compiled/<slug>.json

  • Published outputs: publish/<audience-or-project>/ or the configured publish output directory

Keep canonical memory in notes/. Treat raw/ as evidence and views/ / compiled/ as rebuildable until promoted.

Safe agent write patterns

OpenClaw integrations should make the smallest useful write, preserve provenance, and run lint/check commands around changes.

Append daily notes

Daily capture is the safest canonical write because it is chronological and easy to review.

Before:

* 2026-05-20

** Inbox

Agent append:

*** Observation
:PROPERTIES:
:ID: obs-2026-05-20-fran-vet-reminder
:CELORGA_SOURCE: openclaw:chat
:CELORGA_CAPTURED_AT: 2026-05-20T16:10:00-07:00
:CELORGA_REVIEW_STATUS: reviewed
:CELORGA_CURATED: true
:END:
Fran needs her heartworm medication refill checked this week.

Rules:

  • Append under an existing day/inbox heading when possible.

  • Add a stable ID for any entry that may be linked later.

  • Use CELORGA_SOURCE and CELORGA_CAPTURED_AT for provenance.

  • Avoid rewriting unrelated daily content.

Create or update TODOs

Agents may add clear task candidates to daily/ or a project note. If the source is generated or uncertain, mark it for review.

** TODO Send follow-up to Dana about launch checklist
SCHEDULED: <2026-05-21 Thu>
:PROPERTIES:
:ID: todo-2026-05-20-launch-followup-dana
:CELORGA_SOURCE: file:raw/meetings/2026-05-20-launch.transcript.org::128-135
:CELORGA_REVIEW_STATUS: review-required
:END:
Candidate from meeting transcript. Verify owner/date before acting externally.

Do not mark externally consequential tasks as done, send messages, create tickets, or change third-party state unless the human explicitly approves that side effect.

Promote generated summaries

Generated drafts belong in views/ first:

:PROPERTIES:
:ID: view-2026-05-20-team-sync-summary
:CELORGA_ARTIFACT_ROLE: view
:CELORGA_PROVENANCE: file:raw/meetings/2026-05-20-team-sync.transcript.org
:CELORGA_GENERATOR: openclaw meeting-summary adapter=work-summary model=example-model
:CELORGA_GENERATED_AT: 2026-05-20T23:00:00Z
:CELORGA_SOURCE_HASHES: file:raw/meetings/2026-05-20-team-sync.transcript.org=sha256:...
:CELORGA_REVIEW_STATUS: review-required
:END:

* Summary
- The team agreed to defer billing launch until the migration checklist is complete. [cite: file:raw/meetings/2026-05-20-team-sync.transcript.org::88-94]

* Candidate TODOs
** TODO Confirm migration owner
:PROPERTIES:
:CELORGA_SOURCE: file:raw/meetings/2026-05-20-team-sync.transcript.org::101-106
:CELORGA_REVIEW_STATUS: review-required
:END:

After human review, promote only accepted content into notes/ and mark it curated:

* Billing launch migration
:PROPERTIES:
:ID: mem-billing-launch-migration
:CELORGA_SOURCE: file:raw/meetings/2026-05-20-team-sync.transcript.org::88-106
:CELORGA_PROMOTED_FROM: file:views/meeting-summaries/2026-05-20-team-sync.org
:CELORGA_REVIEW_STATUS: reviewed
:CELORGA_CURATED: true
:END:
The team deferred billing launch until the migration checklist is complete.

** TODO Confirm migration owner

Add backlinks and linkify output

Prefer deterministic previews before mutating notes:

celorga roam linkify --dir notes --recursive --dry-run
celorga roam linkify --dir notes --recursive --apply
celorga lint --dir . --recursive

Generated link suggestions from AI should be written to views/link-suggestions.org with citations and review-required status. Apply only reviewed links to notes/.

Avoid duplicate IDs

Before assigning an ID, search or lint the corpus. Use IDs that include date, entity, and purpose instead of random duplicates:

obs-2026-05-20-fran-vet-reminder
mem-billing-launch-migration
todo-2026-05-20-launch-followup-dana
view-2026-05-20-team-sync-summary

Run celorga lint after writes so duplicate IDs, stale provenance, invalid artifact metadata, and unsafe generated artifacts surface immediately.

Lint before and after writes

For automated write flows, use this shape:

celorga lint --dir . --recursive
# perform one focused write
celorga lint --dir . --recursive

If the pre-write corpus is already dirty, record the existing diagnostics and ensure the integration does not introduce new ones.

Memory promotion lifecycle

Memory promotion is a reviewed state machine with explicit source boundaries.

1. Raw observation or transcript → candidate note

  • Capture source material in raw/ or append an observation to daily/

  • Preserve timestamps, source refs, and source hashes when available

  • Generate summaries or extracted facts into views/, not notes/

  • Every generated factual claim cites source material or says evidence is missing

2. Candidate note → reviewed durable memory

A human or trusted review workflow verifies the candidate, edits wording, removes unsupported claims, and promotes accepted content into notes/.

Required promoted-memory properties:

:PROPERTIES:
:ID: mem-<stable-slug>
:CELORGA_SOURCE: file:raw/...::line-line
:CELORGA_PROMOTED_FROM: file:views/...
:CELORGA_REVIEW_STATUS: reviewed
:CELORGA_CURATED: true
:CELORGA_CURATED_AT: 2026-05-20T23:30:00Z
:END:

3. Old memory → updated, merged, or deprecated

Do not silently overwrite old durable memory. Prefer an explicit update trail:

:PROPERTIES:
:ID: mem-old-launch-date
:CELORGA_REVIEW_STATUS: reviewed
:CELORGA_MEMORY_STATUS: deprecated
:CELORGA_DEPRECATED_BY: id:mem-current-launch-plan
:CELORGA_DEPRECATED_AT: 2026-05-20T23:45:00Z
:END:

For merges, keep backlinks from deprecated nodes to the surviving memory so old references remain explainable.

4. Generated claims cite source material

Acceptable generated claim:

The billing launch was deferred until migration checklist completion. [cite: file:raw/meetings/2026-05-20-team-sync.transcript.org::88-94]

Unsafe claim:

The billing launch is delayed because the payments provider failed certification.

If the source does not support the reason, the generated artifact should say Evidence missing or leave a review question.

Use normal Org property drawers. Recommended properties:

Never store API keys, OAuth tokens, cookies, or private provider credentials in Org properties, job manifests, compiled artifacts, or published output.

Deterministic transforms vs review-gated side effects

Celorga deterministic transforms are local, reproducible operations over files:

  • parse, format, lint, agenda, query, compile corpus

  • generate backlinks and linkify previews

  • export/publish from reviewed source

  • produce cited context packets in compiled/

  • write deterministic reports whose inputs are local files

These may be automated when they write only generated zones or reviewed deterministic output.

Review-gated AI or external side effects require a human approval boundary:

  • LLM-generated summaries, extracted claims, inferred TODOs, entity matching, and link suggestions

  • promotion from views/ into canonical notes/

  • edits that delete, merge, or deprecate durable memory

  • sending email/chat, opening or updating Linear/GitHub tickets, calendar changes, or other third-party writes

  • publishing externally visible output if it contains private or newly generated claims

Rule of thumb: deterministic Celorga transforms can build and check the map; AI and external tools can propose changes; reviewed promotion decides what becomes territory.

Meeting processing flow

Example flow from transcript to curated note:

# 1. Capture raw transcript.
mkdir -p raw/meetings views/meeting-summaries notes/meetings compiled
cp ~/Downloads/team-sync.txt raw/meetings/2026-05-20-team-sync.transcript.org

# 2. Build cited local context deterministically.
celorga query "team sync" \
  --dir raw/meetings \
  --recursive \
  --subtree \
  --answer-context \
  --format json \
  > compiled/2026-05-20-team-sync-context.json

# 3. Ask AI to write a reviewable draft, not canonical memory.
celorga ai run \
  --task summarize-meeting \
  --context compiled/2026-05-20-team-sync-context.json \
  --out views/meeting-summaries/2026-05-20-team-sync.org \
  --apply

# 4. Check generated artifact metadata and graph health.
celorga lint --dir . --recursive

# 5. After review, promote accepted content.
celorga ai promote \
  --file views/meeting-summaries/2026-05-20-team-sync.org \
  --to-file notes/meetings/team-sync.org \
  --apply

# 6. Re-check canonical corpus.
celorga lint --dir . --recursive

Before promotion, the draft is a view artifact with review-required status. After promotion, the accepted note in notes/meetings/team-sync.org carries source/provenance properties and the draft can be marked promoted.

Integration checklist

Before writing:

  • Identify the target zone: raw/, notes/, compiled/, views/, or publish/.

  • Decide whether the operation is deterministic or review-gated.

  • Run or inspect recent celorga lint output when practical.

  • Search for existing IDs/entities to avoid duplicates.

  • Prepare provenance: source path/message ref, line range, hash, generator, and timestamp.

When writing:

  • Append or patch the smallest relevant section.

  • Write generated or uncertain content to views/ with review-required.

  • Keep secrets out of files.

  • Include citations for generated factual claims.

  • Do not perform external side effects from generated TODOs without approval.

After writing:

  • Run celorga lint --dir . --recursive or the repository's equivalent check.

  • Confirm no duplicate IDs or invalid review/provenance metadata were introduced.

  • If promoting memory, ensure the promoted note says where it came from and the source draft is marked reviewed/promoted.

  • If publishing, verify the output contains only intended reviewed content.
