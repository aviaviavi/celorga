VS Code

Celorga's most complete editor integration today is VS Code.

Install instructions

Install the CLI first:

npm install -g celorga
celorga --help

Then install Celorga for VS Code from the Visual Studio Marketplace.

Open your notes folder and run Celorga: Open Agenda from the command palette.

In .org files, formatting and save-time shorthand handling rewrite fenced blocks and backtick inline code to ordinary Org syntax.

Source install

For extension development or unreleased builds, use the repository copy in the editors/ directory.

  1. Build Celorga CLI and repository artifacts:

git clone https://github.com/aviaviavi/celorga.git
cd celorga
npm ci
npm run build

  1. Install extension dependencies:

cd editors/vscode-*
npm ci

  1. Install/run the extension:

  • Use VS Code Extension Development Host from this folder, or

  • Package to VSIX and install via Install from VSIX....

  1. Ensure the celorga CLI is available:

  • Repo-built fallback is supported, or

  • Provide celorga on your PATH.

For settings and command behavior details, see the extension's README.md and Tooling reference.

  • celorga.cryptDecryptSubtree

  • celorga.cryptEncryptSubtree

  • celorga.cryptReencryptSubtree

Set celorga.crypt.recipients to the default GPG recipients that should be able to open newly encrypted subtrees, such as your personal/device key plus an agent key. celorga.crypt.recipientFiles can point at armored public-key files. VS Code passes those recipients through to the CLI for encrypt/re-encrypt, while decrypt can still use the unlocked matching private key.

For selective sharing, put recipients on the subtree itself instead of in global VS Code settings:

* Private note shared with an agent :crypt:
:PROPERTIES:
:CRYPT_RECIPIENT_FILE: keys/agent-public.asc
:END:
This body is encrypted to the listed recipient file when you run Celorga: Crypt Encrypt Subtree.

:CRYPT_RECIPIENT: / :CRYPT_RECIPIENTS: accept GPG recipient identifiers. :CRYPT_RECIPIENT_FILE: / :CRYPT_RECIPIENT_FILES: accept armored public-key files. Relative file paths are resolved from the Org file containing the subtree, which keeps shared corpora portable across devices.
