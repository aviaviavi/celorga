Celorga for macOS

A native workspace for local notes, planning, meetings, and agent work.

Celorga brings an ordinary folder of .org files into one Mac app. Your files remain the source of truth, so you can also read, edit, sync, or version them with tools you already use.

Start with an agent and today's note

On first launch, Celorga creates a plain-text workspace automatically and asks you to connect an agent already available on your Mac. Choose local Codex, local Claude Code, or an OpenClaw Gateway you already run. You can also continue without AI; Celorga does not require an account or agent.

After setup, Home opens immediately with a chat box and today's daily note side by side. Ask a question, write in the note, or do both. The initial workspace lives in a normal folder that you can move or rename. Use Celorga → Settings… → General to update its portable name and kind, reveal it in Finder, or open a different corpus.

If you already keep notes in another folder, choose it from the workspace options during setup or mount it later from the corpus switcher. Celorga derives its views without moving your source of truth into a private database.

Global capture works anywhere on your Mac while Celorga is running. Press Cmd-Ctrl-Return to add a note or task to today's daily note, including dates, tags, links, files, or images.

Celorga stores daily notes in the corpus's daily/ zone by default. Set roam.dailiesDir in celorga.json to a valid absolute path or a directory relative to the corpus root to use a different location; missing or invalid values fall back to daily/ rather than the corpus root. Celorga creates a missing daily note when you navigate to it by default. To let another job own creation, enable Disable automatic daily note creation in Settings → General. Daily links then open existing files only and offer Create Daily Note when the target is missing.

If you already keep dailies under your own names, open Settings → General → Daily Note Format (or Use My Own Daily Notes… on the missing-note screen) and choose one existing daily note. Celorga infers a path format from it, for example ops/{YYYY}/{MM}{DD}-startup.md, previews yesterday, today, and tomorrow, and saves the format to celorga.json as roam.dailyFileTemplate. Home, Today, Yesterday, Tomorrow, Cmd-7 through Cmd-9, the date picker, and date-mention links then open that file. New Markdown dailies start with a # title. One format applies per corpus; choose Use Default to return to daily/YYYY-MM-DD.org.

The workspace

Settings → General → Send launch telemetry, the last setting on that page below Experimental features, controls one background event sent to Scarf each time the production Mac app starts. It is enabled by default and applies to all workspaces on this Mac. The event contains only the event name, app version, macOS version, CPU architecture, and telemetry schema version. It includes no notes, chats, file paths, or installation identifier. Scarf receives the request's network address for processing and network-level analytics. Disable the switch to stop future launch events, or set DO_NOT_TRACK to 1 or SCARF_ANALYTICS to false in the launch environment. Telemetry failures do not interrupt startup or retry; Preview, smoke-test, and headless server processes do not send launch events. Daily Celorga builds send launch events in both debug (local-fast) and release configurations; telemetry eligibility depends on the production bundle identifier, not compiler optimization. This measures launches, not clicks, editing, or chat activity.

Settings → General → Usage Log is a separate, local-only switch, off by default. When on, Celorga appends interaction events to usage-events.jsonl in its Application Support folder: how documents are opened (Quick Open, links, sidebar, backlinks, back and forward), how long they take to appear, Quick Open rank and query length, Start Work, chat turn start and finish times, and Activity view use. Events carry counts, durations, labels, and salted per-install hashes of file paths, never note text, chat text, titles, search queries, or file names. Nothing is uploaded. Show Log in Finder reveals the file so you can read it or share it yourself, and Clear Log deletes it. The file rotates at 5 MB, keeping one previous file.

Agenda

see scheduled work and deadlines across one or all open corpora. Filter by date, assignee, status, priority, topic, or text; mark items done, reschedule them, change priority, or open the source note.

Calendar

see your synced Google Calendar sources and agenda TODOs on one day, week, or month grid (Cmd-Option-K). Each Google Calendar source gets its own color and can be hidden from Show; declined events and completed TODOs are hidden unless you turn them on. Timed TODOs sit on the time grid for their Effort (half an hour by default); untimed ones join the day's all-day row, most urgent first, and a busy day folds the rest into +N more. Open TODOs from past days are gathered once into the red overdue button instead of repeating on every past day. Click any event or TODO for its details: Ask AI starts a chat with the event's synced record and its linked notes as context (or the TODO's heading), and events also offer Join, Record when the meeting is about to start, and Open in Google Calendar. Web addresses in an event's description, such as a Zoom or Meet link, are clickable. Linked notes are exact matches only: the meeting note recorded for that event (:calendar_event_id:), a note titled like the event, earlier meeting notes with the same title, and attendees' person notes. TODOs can be opened, marked done, or rescheduled from the same popover or their right-click menu. Sync runs every Google Calendar source now, and Full Width closes the document pane when it is open.

Files

expand the cached corpus file tree directly in the sidebar, or use the full tree and search surface for Org, Markdown, CSV, and generated workspace files. The + button beside Files, File → New File…, or Cmd-Shift-N creates a note, draft, or scratch file: enter a name and a corpus-relative folder (default notes, or the corpus's roam.nodesDir). A name such as Launch post becomes notes/launch-post.org with #+TITLE: Launch post, a stable :ID: and a :CREATED: timestamp; a name ending in .org, .md or .txt is used verbatim. The sheet previews the path, refuses paths outside the corpus, never overwrites an existing file, and opens the new file.

Activity

see what is happening across the corpus at a glance (Cmd-Option-N). Now starts with Agents: one row per connected agent (each enabled chat destination, plus any agent with live or waiting work), marked Working, Needs you, or Idle. A working agent shows what it is working on and the step its runtime last reported, such as a tool call; an idle agent shows when it last worked and in which chat. Click a row to open that work. Below it, Now lists what needs you (approvals, blocked runs, agents waiting on your reply), what agents are working on and where, scheduled automations, files changed today, and the files you were recently in. Several approvals from one run appear as one row with a count. Activity shows only current work: running or queued runs updated in the last day, blocked runs and runs waiting on you from the last week, and failures from the last three days. Older open runs are counted at the bottom of the list, with a link to Runs. Each section shows five rows until you choose Show all, and files under hidden folders such as .celorga/ are not listed as changes. Map lays the same signals over the corpus as a folder treemap: tiles are sized by files and activity and badged for attention, live agent work, schedules, and today's edits. Click a folder to zoom in and a file to open it. Every agent row has an Explain Status inspector (the ⓘ button or the row's context menu). It shows why the thread, run, approval, or automation is in its state, which host and runtime reported it, the last heartbeat or transition, whether that is Live, Cached, or Uncertain (for example, a laptop that stopped sending heartbeats mid-turn), and the exact blocking approval or question with Open in Review and Copy Command actions. The inspector reads the same structured explanation as celorga activity explain. The Hosts section lists this Mac, headless servers and other Macs sharing the corpus, and SSH or endpoint agent harnesses, with an online, reconnecting, sign-in-needed, stale, offline, or on-demand state, active work and needs-you counts, last-seen time, where turns execute, which host owns automations, and which online hosts could take over (failover). A disconnected host's last-known turns stay visible but dimmed.

Agent Work

follow delegated runs, inspect outputs and citations, and handle decisions that need you. Review Queue and Automations also have direct top-level sidebar entries; press Cmd-Shift-R or Cmd-Option-A to open them immediately.

Meetings

record or import audio and keep transcripts, summaries, decisions, and follow-ups together.

Sources

connect supported external sources such as Slack, Notion, and email (IMAP) from one Add Source form, run a sync, or control its schedule.

Skills

inspect workspace-authored agent procedures, open their SKILL.md source, create a new skill, or move one to the Trash.

AI Chat

talk with any configured local, remote, hosted, or self-hosted destination using selected workspace context.

Search and Quick Open

find text, tasks, files, people, projects, meetings, agent work, and chat threads without remembering where they live. Search → This Mac finds any file or folder on the Mac, not just in the corpus (see Finding files on this Mac).

Open Settings → Appearance to choose a theme for each system appearance. System follows macOS and switches between your light and dark themes automatically; Light and Dark hold Celorga on one of them. Each theme appears as a small preview showing headings, TODO states, planning lines, links, inline code, and comments. Alongside the Celorga Paper and Night defaults are palettes adapted from popular Emacs themes, including Modus, Leuven, Solarized, Gruvbox, Spacemacs, Doom One, Catppuccin, Dracula, Nord, Zenburn, Monokai, and Tokyo Night. Themes change the workspace chrome, rendered documents, the Org source editor, and AI chat. They are preferences for this Mac and are not written to the corpus.

Click a sidebar section header (Workspace, Pinned, Daily, Files, Projects, or Chat) to collapse or expand that section. Every header uses the same style, so a fully collapsed sidebar reads as one uniform list. Celorga remembers which sections are collapsed across relaunches.

You can open several corpora and switch between them from the sidebar. Agenda and Search can read across all mounted corpora, while writes stay scoped to the active corpus.

Use tabs to keep several documents or workspace views open without mixing their navigation history, selected surface, surface mode, row selection, or two-pane layout. An Agenda tab therefore returns to Agenda, while an Agent Work or Skills tab returns to its own view and selection. Press Cmd-T for a new tab and Cmd-Shift-[ or Cmd-Shift-] for the previous or next tab. Drag tabs to reorder them, or right-click one to duplicate, move, close, or close the other tabs.

Open Skills from the sidebar or press Cmd-Shift-K. Skills are ordinary SKILL.md files under .agents/skills/. Select a workspace-authored skill to edit it in the normal document pane, use New Skill for a safe starter file, and use the row menu to reveal it or move its whole folder to the Trash. Invalid skill files remain visible with a repair message instead of disappearing from the manager.

Celorga supplies its core operating guidance ambiently to every AI chat, so the reserved general Celorga skill is not shown as a user workflow or slash command. Its corpus copy remains available to external skill-aware agents. The Skills surface is for additional procedures authored for this workspace.

From a TODO to agent work

Every open TODO heading in the rendered document shows ▶ Start work… on hover, and Start Work with AI… is in the heading's right-click menu and in Agenda's row menu. A small dialog first asks where to start: the thread (the heading's own thread, a new thread, or the AI chat thread you have open), the agent profile, the harness, the model, and the reasoning effort. A heading's own :AGENT_REF: takes precedence, an existing thread keeps its harness, and a new thread starts on the destination chosen in Settings → AI Chat → Agent Work → Run new agent work with (or, without one, your last Start Work choice). No runtime is a built-in default. Starting work then:

  1. creates and starts a durable celorga run that cites the heading,

  2. adds :CELORGA_RUN_ID: to the heading (and an :ID: if it has none) and moves a TODO to in progress,

  3. sends the chosen thread the task, the source reference, and the run ID. The thread shows that message as a compact Start work card with the task and its source; Show prompt reveals the exact text the agent received.

The heading then carries a live badge: Working while the agent replies, Your turn when it has replied and the run is still open, Needs you when the run is blocked or waiting for approval, Failed, or Done. Agenda rows show the same badge. Click it to return to the conversation. Starting work on a heading whose run is still open reopens that thread instead of creating a second run. Agents that can use the Celorga CLI are asked to record an outcome under the heading and close the run with celorga run complete.

Write and read

Celorga offers two views of the same document:

  • Read renders headings, links, properties, tables, citations, media, source blocks, and other Org structure.

  • Edit Source provides a native macOS text editor with syntax highlighting, folding, diagnostics, list continuation, TODO and planning commands, link insertion, undo, and safe saving.

While editing, type @ to link a corpus file or insert a date. The editor offers the same files as @ in AI Chat, ranked the same way: a bare @ lists files, and @plan or @reading_list narrows them. Choosing a note inserts an id: link labeled with its title when the note has a unique ID, and otherwise a file: link relative to the current document. @today, @tomorrow, @yesterday, month-day forms such as @july 10 or @jul 10 2025, and numeric forms such as @7/10 or @2026-07-10 also offer an Org date stamp such as <2026-07-10 Fri> and, when that day's daily note exists, a file: link to it; dates are listed before files. Use the arrow keys to choose, Tab or Return to insert, and Esc to dismiss. Dates without a year use the current year. Chat's agent destinations and @all are not offered in documents because they route chat messages rather than link to content.

Type /image at the start of a line or after a space to embed an image while you write. Choosing the command opens a file picker. An image from outside the corpus is copied into the corpus's attachments/ folder, so it renders on every Mac the corpus syncs to; an image already in the corpus is linked where it is. Celorga inserts a [[file:…]] link relative to the current note. Paths such as /Users/… and words such as and/or never open the command panel.

Right-click a heading in the rendered view for entry actions, including Move / Refile… and Archive Entry. Archive Entry moves the heading and its subtree to the note's _archive file (notes.org archives to notes.org_archive), the same as celorga archive, and records where it came from in ARCHIVE_* properties.

Checked list items, such as - [X] Ship the fix, are shown struck through and muted in the source editor and the rendered view. Nested items keep their own state.

An image link without a description, such as [[file:attachments/chart.png]] or [[/Users/me/Desktop/shot.png]], renders as the image in the rendered view, including when text surrounds it. A link with a description inside a sentence stays a text link. Relative paths resolve from the note's folder first, then from the corpus root. Notes can show images anywhere on this Mac through an explicit absolute or ~/ path, but such an image appears only on Macs that have that file; use /image to keep it with the corpus. AI chat replies show only images inside the corpus.

Prose is a third editor presentation beside Source and Split. It uses the same native editor and the same Org text, with a proportional serif face, generous line spacing, a readable centered column, and editing syntax concealed. Select a word, sentence, or paragraph, then use the Prose toolbar or the editor's context menu:

  • Add Alternative… enters another version. The new version replaces the text in the document; the original and any earlier versions stay recoverable. Step through versions with the toolbar arrows or Control-Option-[ and Control-Option-].

  • Ghost fades text without deleting it; Revive brings it back, and Reveal Ghosts shows all ghosts at reading strength.

  • Move to Overflow parks the selection in a side panel. Restore puts it back at its original spot. If that spot can no longer be found, Restore at Cursor inserts it at the insertion point, and the fragment is never discarded implicitly.

Revise with AI… (Control-Option-R, also in the toolbar and context menu) is the one model-assisted Prose action, and it runs only when you ask. Type an instruction such as "tighter" or "friendlier", choose one of the direct model providers set up in Settings → AI Chat (OpenAI, Anthropic, OpenRouter, Ollama, or an OpenAI-compatible endpoint) and a model; Celorga remembers the last choice. It sends a single text request containing the instruction, the selection, and a bounded amount of surrounding prose, with no tools, no agent turn, and nothing else from the corpus, and you can cancel it while it runs. The reply becomes a new version of that span and is made active in one undo step. The original stays one step away, versions are cycled like any other alternative, and the side panel marks AI versions with the provider, model, instruction, and time they came from. If the text changed while the request ran, nothing is applied. With no direct provider configured, the popover links to the AI Chat settings.

Except for Revise with AI, everything above is manual and local. The reversible state lives in one #+BEGIN_COMMENT block that starts with a versioned prose-state marker, visible in Source mode and hidden in Prose mode; it is added only when you first use a Prose action. Each record stores its text and a little surrounding context, and Celorga re-attaches it conservatively after ordinary edits. Ambiguous or stale records stay listed as unresolved in the side panel instead of attaching to different prose. A block that cannot be read is never rewritten: Prose actions turn off and the block's text is left as it is. Every Prose action is one undo step.

Vim mode (off by default) gives the Source, Split, and Prose editors Vim keybindings. Turn it on in Settings → Documents → Source Editing. A small mode line in the editor's lower-right corner shows the mode, pending keys, macro recording, messages, and the : or / command line. Supported:

  • Normal, Insert, Replace, and Visual modes (character, line, and block), with a block cursor outside Insert mode.

  • Counts on motions, operators, and inserts; . repeat, including Visual and Insert changes.

  • Motions: h j k l, w b e ge and their WORD forms, 0 ^ $ g_ |, gg G, f t F T ; ,, % { } ( ), H M L, gj gk, marks with ' and `, / ? n N * #, and jumps with Ctrl-O and Ctrl-I.

  • Operators d c y > < g~ gu gU g? with motions, text objects (iw aw iW aW is as ip ap, quotes, brackets, and tags), doubled lines such as dd, and search targets such as d/word.

  • Commands x X D C s S Y p P gp gP J gJ r ~ R o O i a I A gi gv, Ctrl-A and Ctrl-X on numbers, u and Ctrl-R, scrolling with Ctrl-D Ctrl-U Ctrl-F Ctrl-B Ctrl-E Ctrl-Y zz zt zb, Visual-block I and A, and Insert-mode Ctrl-W Ctrl-U Ctrl-R Ctrl-O Ctrl-T Ctrl-D.

  • Registers: unnamed, a–z (uppercase appends), 0–9, -, + and * for the system clipboard, _, ., /, and :. The unnamed register follows the system clipboard, like clipboard=unnamed; :set clipboard= keeps them separate.

  • Macros with q and @, @@, and @:.

  • Command line: :w, :wq, :x, a line number, ranges (%, ., $, marks, '<,'>, patterns, offsets), :s with g i I n flags, & and :&&, :d, :y, :j, :> and :<, :m, :t, :pu, :normal, :g and :v, :sort, :undo, :redo, :marks, :registers, and :set for ignorecase, smartcase, shiftwidth, expandtab, wrapscan, and clipboard. Search patterns use Vim syntax, including \< \>, \( \), \|, \c, and \v.

  • Org structure: Tab and za fold or unfold the heading, zR unfolds everything, and [[ and ]] move between headings.

Keys follow the active keyboard layout, so Dvorak, Colemak, AZERTY, and other layouts type the characters printed on their keys. Command-key shortcuts keep working in every mode. In Insert mode, typing goes through the normal editor, so list continuation, completions, and input methods behave as usual. o on a list item opens the next item (bullet, number, or checkbox) the way Return does, and on a heading with no body it opens a sibling heading; a heading with a body or drawer keeps it, so o opens a plain line. u undoes a whole Vim change, such as cw plus the text typed after it. ⌘Z still undoes AppKit's smaller steps. Not supported: Vim script and mappings, folds you define yourself, windows and buffers, and :! shell commands. :q does not close the document; use ⌘W.

Hover a link in the rendered view for about half a second to preview it. id:, file:, and other workspace links show the target heading's title, its corpus path and line, and the first lines of its body; previews are cached until the target file changes. Web links show the link's description and full URL; Celorga does not load the page to build the preview.

An optional split view keeps source and rendered preview visible together. Rendered tables can be filtered, sorted, and resized without changing the source. CSV files open in an editable table with a raw-text fallback.

Code and plain-text files linked from a note or an AI chat reply open in the detail pane as read-only source with syntax highlighting instead of being read as Org markup. The shared highlighter covers more than 60 languages and 300 extensions and file names across programming languages (Python, JavaScript/TypeScript, Swift, Go, Rust, Java, Kotlin, C/C++Objective-C/CUDA, C#, Ruby, PHP, Dart, Zig, Julia, Haskell, OCaml, F#, Elixir, Erlang, Lisp/Clojure, Lua, R, Scala, Perl, Nim, Crystal, Solidity, Verilog, VHDL, Fortran, assembly, and more), markup (HTML/XML/SVG, Svelte, Vue, templates, Markdown, LaTeX, diffs), configuration (JSON, YAML, TOML, INI.editorconfig, HCL/Terraform, Nginx, CMake, Dockerfile, Makefile, .env, .gitignore, Bazel, Gemfile/Jenkinsfile and similar named files), data and schemas (SQL, GraphQL, Protocol Buffers/Thrift, Prisma, Jsonnet), and shells (sh/zsh, PowerShell, batch). Every line stays addressable, so a link such as file:tool.py::27 scrolls to line 27, and long files are never collapsed. Source blocks in the rendered view use the same highlighter. Highlighting is native to the renderer and loads no script into the document. The Source editor highlights the same files natively as you type, using the language table generated from the shared highlighter, and turns off Org-only writing commands, spelling, and Org analysis for them.

HTML files (.html, .htm, .xhtml) open as rendered web pages in the detail pane, with relative stylesheets, scripts, and images resolved inside the corpus. The page reloads when the file or an asset beside it changes. Source or File → View HTML Source switches to the highlighted source and editor, Open in Default Browser hands the file to your browser, and Serve Folder serves its folder over loopback http and shows it in the detail pane.

AI chat's reviewed workspace edits can create and update .html, .htm, and .xhtml files, with the same preview, stale-write protection, and undo as notes. Link the saved file to open its rendered page.

Completed #+begin_src html blocks render directly in AI chat and the document reader as live previews, with an expandable HTML source disclosure and the usual copy button. Markdown HTML fences also work in chat. JavaScript runs, so a reply can be an interactive chess board, simulation, calculator, or chart instead of a picture of one. Scripts, styles, fonts, images, and data can load over HTTPS. Each preview grows or shrinks to fit its content, up to 1,600 points; #+begin_src html :height 480 fixes the height instead. The preview runs in an opaque-origin sandbox: its styles and scripts cannot read or change the surrounding document, the chat, the corpus, local files, or the app, and it cannot navigate the window, open nested frames, or submit forms to a server. Links inside it open in the detail pane. Plugin renderers, such as the chess PGN example, run their scripts in AI chat the same way. An unfinished streaming block stays source until its closing delimiter arrives. Ordinary HTML exports and the HTML file's Source view retain code rather than becoming previews. The iOS app shows these previews without running scripts.

Clicking a web link (http or https) in a note, a rendered document, a canvas, or an AI chat reply opens the page in the detail pane, the same way a file link opens a note, whatever the linked file type. Back and Forward move between the page and the documents you opened before and after it; Cmd-click opens the page in a new tab. The page bar has its own previous/next page, reload, and an address field that accepts full URLs, bare host names, local development servers such as localhost:5173 or a private-network address (opened over http), file paths, and otherwise runs a web search. Its server menu lists development servers already running on common local ports and Serve Folder…, which serves a folder (for example a built static app) read-only over http on 127.0.0.1 only; each served folder can be reopened or stopped. Open in Default Browser (the Safari button) opens the current page outside Celorga. Cmd-F opens a find bar for the page (Return or Cmd-G for the next match, Shift-Cmd-G for the previous one, Esc or Done to close it). Cmd-+ and Cmd-- zoom the page; the zoom percentage appears in the bar and clicking it returns to actual size. The ⋯ menu also has Find in Page…, Copy Link, and the zoom commands. The expand and close buttons at the end of the bar work as they do for documents: expand gives the page the whole window, and close hides the pane. mailto: and app links still go to macOS. Cookies and site data use the system web data store.

PDFs, images (PNG, JPEG, GIF, TIFF, BMP, HEIC, and WebP), and videos (MOV, MP4, and M4V) linked from a note or an AI chat reply open in the detail pane's native file view instead of an external app. Images fit the pane, with an Actual Size toggle; animated GIFs play. Videos use the standard macOS player controls. The view reloads when the file changes on disk, and Open in Default App remains available from the source menu.

Large source blocks, including run machine-state JSON, start collapsed in the HTML reader and preview. Open the source disclosure to read or copy the complete block. Ordinary HTML exports remain expanded.

Trusted Celorga plugins can add renderers for source-block languages. The shared CLI HTML runtime powers both read mode and source preview, so the same plugin also works in celorga export html without a separate Mac extension or app rebuild. Renderer UI runs in a sandboxed, opaque-origin frame. See Tooling reference → Plugins.

Plugins can also contribute context-aware actions. The document File menu shows Plugin Actions for Heading and Plugin Actions for Note, and Activity row context menus show actions for chat threads, runs, and approvals. An action runs sandboxed without corpus write access; its output and any proposed changes open in a review sheet with unified diffs, and nothing is written until you choose Apply Changes. Lifecycle hooks (for example on run.blocked or approval.requested) are dispatched by the corpus's automation host, and their proposals appear under Needs you in Activity for the same review.

Celorga can export an ordinary document or selected subtree as a clean PDF. Document PDFs preserve styled headings and content while omitting heading stars, outline guides and their indentation, disclosure arrows, property drawers, and interactive controls such as Ask AI. It can also preview slide decks and export presentation PDFs. Publication uses a disclosure-safe copy that removes private workspace metadata and unresolved local references from the shared output.

Finding files on this Mac

Choose This Mac in Search (Cmd-Shift-F) to find any file or folder on the Mac by name, not just the files in your corpus. It works even when Spotlight is turned off.

  • Results update as you type. Every word has to match the file's name or a folder it is in, so finance cap table finds Cap Table.xlsx inside Finance. A word can match the start of a word in the name, and words can run together, so soc2 finds SOC 2 Report.pdf.

  • Recently changed files rank first, and documents rank above files inside source code repositories.

  • Repeat downloads and copies show up as one result: the newest file, with a badge such as +12 older copies. This covers Report (3).pdf, Report copy.pdf, Report-2.pdf next to Report.pdf, and the same document filed in several folders. The row's context menu lists the older copies and marks the ones that are byte-for-byte identical (local files up to 64 MB).

  • Narrow the results by typing kind:pdf, kind:sheet, kind:slides, kind:image, kind:folder, or an extension such as .xlsx.

  • With an empty search box, Search shows your recently changed documents.

  • Double-click or press Return to open a result (corpus files open in Celorga), and press Cmd-Return to show it in Finder. Drag a row into another app or a chat to attach the file. The context menu can also copy the path or an Org link.

By default Celorga indexes your home folder, iCloud Drive, and the cloud drives under ~/Library/CloudStorage (Dropbox, Google Drive, OneDrive). It skips the rest of ~/Library, hidden folders, and build and dependency folders such as node_modules and .git. App bundles and package documents such as Keynote decks count as single files. Use the Folders menu to add or remove folders, return to the defaults, or rebuild the index.

Celorga reads only file names, sizes, and dates. It never reads a file's contents, except to compare small local copies, and it never downloads cloud files. The index is stored in ~/.org2/files/ on this Mac, never in a corpus. The first index takes a little while to build, and results appear while it runs. After that, Celorga updates it as files change while the app is running, and rebuilds it if it is more than six hours old. Agents can use the same index with celorga files search (see File search on this Mac).

Discover connections

Open a note or stable-ID heading, show its Context pane, and choose Graph. Choose 1 hop for immediate incoming and outgoing links or 2 hops for neighbors of neighbors. Click a node to center its neighborhood; drag nodes to arrange the drawing. The arrows point toward linked targets. Search the visible node list and use Open source or a node’s arrow button to navigate to its exact source heading. Current note resets an explored neighborhood to the open document. Notes without IDs display an empty discovery state; add a #+ID: file keyword or an ID property in the heading’s drawer, then refresh.

Unlinked mentions lists exact title and alias occurrences in other files. Use the cited file and line to inspect the source, then click Link to replace that one occurrence with an explicit ID link. When a title or alias identifies several notes, Choose target lists each destination with its file and ID. This choice is always explicit. If the source or target changes before linking, refresh the panel and review the occurrence again. Finish an active source edit before linking into that file.

The panel scans only the active corpus and observes its ignorePatterns. Archives, hidden/build directories, sync conflicts, and symlinks are excluded. Neighborhoods are bounded to 60 nodes and mention results to 200 occurrences; a visible message identifies a truncated result. Refresh rescans source files. Publish a document

Open an Org document, open its document menu, and choose Publish Document…. The same sheet also opens from /publish document in AI Chat. Choose the entire document or the subtree at the current reading/editing position, then inspect the disclosure preview before publishing.

The publish sheet separates the destination from the format:

  • Local Link can serve a read-only Web page, fixed-layout PDF, or compiled Beamer slides (PDF). Web pages use the same fluid, bounded document layout as Celorga's reader; long text wraps, charts shrink with the viewport, and wide tables scroll inside the page instead of widening it. The destination creates a high-entropy secret URL from the Mac and persists its sealed artifact locally. Publishing the same document or subtree and format again updates that URL in place, including links created before stable republishing was introduced. Devices must be able to reach the Mac on the local or private network. Celorga must be running for a link to be reachable, and active links resume at the same URL after Celorga relaunches. The initial server uses unencrypted HTTP, so use it only on a network you trust. Open Settings → Sharing to see every source file, format, and shared chat thread currently hosted, open or copy a link, stop one, or stop all of them.

  • Google Drive can create an editable Google Doc, Google Slides deck, or Google Sheets workbook, or upload a fixed-layout PDF. Slides use the selected content's slide headings. Sheets create one tab per Org table and refuse a selection with no tables. The optional folder ID selects a Drive folder; otherwise Google places the file in the connected account's default location. After the first successful publish, Celorga saves that format's Drive file ID, link, guarded version, and publish time in the selected document or subtree property drawer. The green Google Drive badge beside the document title reopens or copies saved artifacts, and publishing the same scope and format again updates the linked file instead of creating a duplicate. OAuth credentials remain in macOS Keychain and are never written into the source. Google Drive owns sharing and identity. Connect Google Drive opens Google's consent page in the default browser using the desktop loopback and PKCE flow, requests only the per-file drive.file scope, and keeps the refresh credential in macOS Keychain.

Web pages and fixed-layout PDFs embed deterministic chart and plot visualizations. A chart's source table must be inside the published document or selected subtree; publishing never follows a chart reference back into unselected corpus content.

Distributed Celorga builds include the app's registered Google OAuth client, so normal setup is one click on Connect Google Drive followed by consent in the system browser. Users do not create a Google Cloud project or import credentials. Use a custom OAuth client remains available as an advanced option for self-built or separately branded deployments; it accepts the JSON for a client of type Desktop app, not Web application. Celorga masks the paired client secret and stores it only with the resulting OAuth credential in macOS Keychain. Google passwords and OAuth tokens are never pasted into Celorga. See Google's desktop OAuth guide, Google's OAuth overview, and Drive scope guidance.

Property drawers, TODO state, tags, planning and clock data, comments, commented subtrees, dynamic blocks, table formulas, raw HTML, internal IDs, unresolved local links, and runtime data are removed before either destination receives content. Referenced supported raster images are embedded in the sealed artifact.

Share an AI chat thread

Click Share in the AI Chat header, choose where to share from, then click Create Link to host the selected thread as a read-only web page. This Mac uses the same local server as Local Link documents. A paired headless Celorga server hosts the page itself, so the link stays live while the Mac sleeps. The link is copied when it is created. You can also right-click a sidebar thread and choose Copy Share Link. The URL stays the same across relaunches until you choose Stop Sharing in the share popover or sidebar menu, or stop the link in Settings → Sharing.

The page includes only delivered conversation text, assistant replies rendered as Org, and image attachments of up to 4 MB. It leaves out attached workspace context, reasoning, tool activity, queued or failed messages, and live embeds. Links into the workspace are shown as plain text. Only web links remain clickable. Before text reaches the page, Celorga replaces known secret patterns with [redacted secret]: sk- API keys, GitHub, Slack, Stripe, and Google API tokens, AWS access key IDs and secret key assignments, JSON Web Tokens, bearer and Authorization header values, and PEM, OpenSSH, and PGP private key blocks. Encrypted PGP message blocks collapse to [encrypted PGP message]. Redaction is best effort, so review a thread before sharing it. The page runs only two fixed scripts, pinned by hash: one checks the same URL for updates, and one runs the optional guest composer. Like other local links, it uses unencrypted HTTP and a high-entropy secret URL, so share it only on a trusted local or private network. While Tailscale is connected, links hosted by this Mac use its Tailscale address instead of its local network name. Links copied earlier keep working under either address.

For a link shared from This Mac, Let guests send messages (you approve each one) in the share popover lets readers send text messages. It is off for every new link and turns off again when Celorga restarts. While it is on, the page shows a small form for a display name (up to 40 characters) and a text message (up to 1,000 characters), with no attachments. Each submission waits above the thread's composer, where you choose Approve, Edit & Approve…, or Decline. Nothing a guest sends reaches the agent until you approve it. An approved message goes through the thread's normal send path, prefixed with Guest and the guest's name, so the agent knows a guest wrote it. Declined messages are discarded. The guest's page shows whether each of their messages is waiting, approved, or declined. Guest text appears as plain text everywhere and is never rendered as Org or HTML. Posting requires the link's secret token, a per-page nonce header, and a JSON request; requests from another origin are rejected. Each link accepts at most five messages a minute and twenty waiting messages. Turning the option off, stopping the link, or revoking it in Settings → Sharing rejects new messages and clears the waiting ones. Links hosted by a paired server stay read-only.

Shared web pages and chat threads include Open Graph and Twitter card tags (title, site name, and a short summary), so apps that show link previews can display a card when a link is pasted. A document's summary is its #+DESCRIPTION or its first paragraph. A chat's summary is its opening message and message count. The preview shows only text the page already shows. The app showing the preview must be able to reach the link. iMessage and WhatsApp fetch previews from the sender's device, so they work on the same private network or tailnet. Slack and Discord fetch previews from their own servers, so they can show a card only when the link is publicly reachable. A document link created by an earlier Celorga version gets the tags when the document is published again.

To host links on a server, run celorga server pair on the server, then open Settings → Sharing → Celorga Server on the Mac. Paste the pairing link, or enter the server's address and six-digit code, then click Pair. The Mac stores its access token in the Keychain. Share new thread links from sets the default location, and the share popover still lets you pick either location each time. The server renders the page from its own synced copy of the corpus with the Mac's appearance settings. A thread must reach the server through corpus sync before the server can share it. Copy Share Link in the sidebar reuses an existing link, or creates one at the default location. Stop Sharing stops the thread's links in both places. Forget Server stops the server's links, revokes the Mac's access when the server can be reached, and removes the pairing.

AI chat and agents

AI is optional. Celorga does not require a Celorga account, and ordinary note, Agenda, search, meeting, and document features work without an AI destination.

In Celorga → Settings… → AI Chat, you can configure named destinations including local Codex, local Claude Code, local or SSH-hosted Pi and OpenCode, Remote Codex over SSH, OpenClaw, OpenAI-compatible providers, Anthropic, OpenRouter, Ollama, or an OpenAI dot. A remote harness destination names an SSH host and the writable Celorga corpus checkout on that runtime; Celorga expands ~/ on the remote Mac and runs the selected harness in that checkout without copying its credentials into Celorga. Remote Codex starts or attaches to Codex's managed daemon through SSH; legacy WebSocket destinations remain compatible but are not offered as a normal setup choice. API keys are stored in macOS Keychain, not in the corpus.

Add Destination → DeepSeek creates an OpenAI-compatible destination for DeepSeek's API (https://api.deepseek.com) with the inexpensive deepseek-flash model selected; deepseek-v4-pro is also offered. Its API key is stored in Keychain like other providers. Reasoning effort maps to DeepSeek's thinking mode: Off disables thinking, and Low, High, or Maximum set its effort. Automations can select the destination, model, and effort for low-cost background work. The destination is saved as an OpenAI-compatible provider, so older Celorga builds keep it working without the effort control.

An OpenAI Dot destination sends your messages to an OpenAI dot, the always-on ChatGPT agent, in the same conversation you see in ChatGPT. It uses the ChatGPT sign-in that Codex stores on that Mac (~/.codex/auth.json, or $CODEX_HOME), so sign in to Codex with ChatGPT first; Celorga reads the sign-in but never stores or refreshes it. Leave Dot blank to message your primary dot, or enter a dot's name or ID, and use Test Connection to check which dot it reaches. The dot receives only your newest message, because it keeps its own memory, and Celorga shows every message the dot sends until it has been quiet for a few seconds. Dots often acknowledge a request and post the result minutes later, so Celorga keeps checking the conversation for up to three hours after the dot's latest message, until Celorga quits, and adds each later message to the chat it answers. Several chats can share one dot: after the first exchange, a chat's messages are sent as replies to the dot's latest message in that chat, so the dot answers in that reply thread in ChatGPT and its answers return to the right chat. A message that answers no particular message goes to the chat that most recently messaged the dot outside a reply thread, and answers to messages you send in ChatGPT itself stay there. A stopped chat receives no later messages. To follow a dot's whole conversation in one place, choose New → Open /dot/'s Conversation. That pinned chat mirrors every message in the dot's ChatGPT conversation, including messages you send from ChatGPT on another device and results the dot posts on its own, and anything you send from it goes to the dot as an ordinary message. Celorga keeps checking the conversation while it is open, every few seconds after activity and less often while it is quiet, and recovers on its own once Codex refreshes an expired sign-in. ChatGPT keeps the full history: the chat stores only the newest few hundred messages, so even a very long conversation stays quick to open and sync, and Load earlier messages reads older ones from ChatGPT as you scroll back without saving them. Voice calls and attachments appear as short notes. Messages are text only. OpenAI hasn't published an API for dots, so this destination uses private ChatGPT routes that can change without notice.

The chat header’s AI Chat Settings… button opens this settings pane directly. The composer combines model and reasoning effort in one compact pill. Open it to choose a model, adjust supported effort levels with a stepped slider, or reset effort to its default. The destination remains alongside it; narrow panes collapse its label, and very narrow panes put the controls above the send actions. Shared rooms use a compact Models menu for their per-destination choices: each agent's submenu sets its model and, when that agent supports it, its reasoning effort. A room's choices are saved with the thread, and changing an agent's model returns that agent to its default effort. To configure the built-in OpenClaw gateway, choose Edit beside its destination in Settings, then Configure Gateway…; gateway connection and pairing controls appear only in that editor. Brief and inactive-thread preferences live in the shared Conversations section.

Enable Experimental features in Settings → General to reveal the opt-in Workspace tools (experimental) setting in each direct-provider destination under AI Chat. Experimental features are off by default and apply across workspaces on this Mac. Turning them off hides these controls, stops any active bundled agent turn, and returns subsequent turns to ordinary context-only chat; saved per-destination tool preferences are retained.

The bundled agent runs a small TypeScript executor using the Node runtime already shipped inside Celorga; no separate agent harness or Node installation is required. The executor can search the active corpus, read effective file text (including unsaved editor drafts), and propose whole-file edits. Every apply request opens a native review of the original and proposed text. Cancel declines edits for the rest of that turn. Celorga binds tools to the originating turn and authorized corpora, and rechecks the exact preview's hashes before writing. Reviewed file creation can target new nested directories inside the active corpus, including corpus skill folders. Reads and previews do not create directories; applying the reviewed edit creates any missing parents. Paths outside the corpus, including symlink escapes, remain rejected.

This prototype supports text conversations with tool-capable OpenAI-compatible, Anthropic, OpenRouter, and Ollama models; support for an endpoint does not guarantee that every model can use tools reliably. Configure a model and endpoint in the destination, enable workspace tools, then try asking for a cited answer and a small task edit in a disposable corpus. Cloud credentials use the existing Keychain configuration. Local Ollama requires a separately running server and an installed model.

Only one bundled turn runs at a time. Replies arrive after each model step, with tool progress between steps; token streaming, automatic context compaction, restart recovery of an in-flight tool loop, attachments, general shell/browser access, and unattended edit approval are outside this prototype. Stop terminates the helper; the existing chat history and successfully applied file changes remain in Celorga. Each turn has a 12-step limit, a 48-tool-call limit, a 4 MiB context/response limit, and a two-minute timeout per model request. Workspace tools are disabled by default, preserving context-only chat for existing destinations.

To use Claude Code, install it and sign in with claude auth login, then enable Claude Code in AI Chat settings. Celorga starts the local CLI, streams its replies, and resumes the same Claude Code session on later turns. No Anthropic key is copied into Celorga. The Local Agent Permissions setting maps to Claude Code's Plan, Accept Edits, or Bypass Permissions mode.

To use Pi or OpenCode locally, install and authenticate its CLI, then choose the corresponding adapter under Add Destination. For another Mac, add a Remote Pi over SSH or Remote OpenCode over SSH destination with an SSH host such as press.local and the corpus path on that host. Celorga loads OpenCode's available models from that destination; if OpenCode reports an empty catalog, Celorga reloads its background service once and retries. The settings list contains only configured destinations: saving adds one, while Delete removes one after confirmation. A destination referenced by an existing chat must remain configured until that chat is deleted. Celorga streams JSON events from the harness and stores its native session ID so later turns resume the same conversation. OpenCode writes one text part per step; the reply is the final part, and the narration it wrote between tool calls stays in the turn's activity feed instead of running together in the reply. OpenCode turns, local or over SSH, reuse a private warm opencode serve for each permission mode instead of starting one per turn, which removes about a second of startup from every later message; an unused server stops after ten idle minutes, and Stop interrupts the turn's session in that server. Local Agent Permissions controls the tools or permissions exposed for each turn; SSH connectivity and harness credentials remain owned by the remote account.

Add files, headings, selected items, images, PDFs, audio, or other supported attachments as explicit context. Typing @ finds corpus files and destinations. @today, @tomorrow, @yesterday, and dates such as @july 10 add that day's daily note as context when the note exists. Chat text has one selection region across the bounded visible transcript, so a drag can copy across paragraphs, bullets, and consecutive messages without mounting an unbounded history. Selection highlights update directly during dragging, using the displayed native glyph layout without rebuilding the transcript on each pointer movement, including inside agent rounds. Copy buttons on snippets and messages show a green check for two seconds after a successful copy, then return to the copy icon. Copying again restarts that confirmation. Copying a table, either by selecting its cells or using the message’s Copy button, supplies a styled HTML table for rich-text destinations such as email and an aligned Org table for plain-text editors. A selection that spans several cells copies only the rows and columns it covers, and a selection inside one cell copies just that cell's text. A Celorga chat thread ID in a message, for example one pasted from celorga thread list, appears as a link titled with that thread's name; click it to open the thread. IDs that don't match a thread on this Mac, and IDs inside code blocks, stay plain text. In a shared room, mention a destination by name or use @all; every reply remains attributed to the agent that produced it. A mention that reaches a configured agent, including @all, is highlighted in the composer as you type and in sent messages, so an @name left as plain text tells you no agent was addressed. Mentions inside code or verbatim text stay plain. Messages without an @mention go to the room's default agent: the agent of the thread the room was forked from, or else the first agent the room addressed. An @mention routes only that message and never changes the default. Choose a different default, or No agent (post context only), from the composer's Default menu; the choice is saved with the thread. Replying again replaces the earlier pill. The sent message keeps the reply pill in the transcript.

Meetings and external sources

Meetings can be recorded in Celorga or created from an existing audio file. Choose local Whisper, macOS Speech, Fluid Voice, or a custom local command for transcription. The resulting audio, transcript, metadata, and notes remain visible in the corpus. A freshly transcribed meeting can optionally be sent to a named AI destination for a summary or follow-up workflow. When recording starts, Celorga creates the meeting note and opens it beside the meeting list, so you can jot thoughts or paste from chat during the meeting; its list row shows RECORDING. Write in its Notes section or anywhere else in the note. When the recording stops, Celorga saves any pending edits to that note, then fills in the recording metadata and the Transcript section in place and keeps everything else you wrote. Finishing a transcription never switches pages or opens the meeting: the new meeting appears in the list and the status bar reports that it was saved, while you keep working where you are. If the app quits mid-recording, the next launch transcribes the audio into that same note.

AI chat dictation uses the same transcription setting. If the chosen transcriber fails (for example, when the Fluid Voice Local API is not running), dictation falls back to local Whisper and then macOS Speech. If no transcriber produces text, Celorga shows an error and keeps the recording under ~/Library/Application Support/org2/failed-dictations/ so the dictation is not lost.

While a meeting is recording, a pill in the window toolbar shows the state on every page: REC with the elapsed recording time (paused time excluded), Paused, Stopping, or Transcribing until the meeting is saved. Click the pill to open Meetings; its buttons pause, resume, or stop the recording without leaving the current page.

The Sources view manages supported Slack, Notion, and email connections. Add Source offers the same form for every source type: Slack (workspace ID, read mode, channels), Notion (read mode, teamspaces), and email (IMAP server, port, TLS or STARTTLS, user name, mailboxes, optional SMTP server), each with an initial window and its credential. Settings are recorded in celorga.json; the Slack bot token, Notion integration token, or email password is stored only in Keychain. Configure… edits an existing source with the same form, and Set Up with AI optionally hands the setup to an AI chat instead. Email sync reads new mail without marking it read. Each connector can run on demand, pause or resume its schedule, and use a repeating interval or daily time. Schedules run on the host that owns the corpus's automations (automationHostRef); when that is a headless server, the server runs them and this view says so. Imported material is staged for review rather than silently promoted into your canonical notes, and credentials remain outside the corpus.

Saved property views

Choose Saved Views in the workspace sidebar to open live tables and cards made from the active corpus. The landing page explains the feature without scanning the corpus. Describe a result in plain language, such as “Show my unfinished project tasks grouped by project,” or choose an example; Celorga turns that request into a visible draft and queries only its selected folder. Review the matching rows before saving. Existing views appear immediately and run only when selected.

Use Edit View for the advanced builder. Choose Headings, Notes, or Both, optionally narrow the corpus-relative folder prefix, and list columns separated by commas. Built-in columns are title, document, file, kind, todo, tags and id; other names select case-insensitive property keys. Use Add Filter for equality, containment, regular-expression matches, presence, numeric or date conditions, or active/terminal TODO state; choose all/any matching, sort fields, and an optional grouping field. Filter values accept date variables such as {today}, {yesterday}, {today-7d}, {today+1m}, {month} and {year}. The view stores the variable, not the date, so file date is on {today} keeps showing today's dated files tomorrow. Date is on/before/after compares the first YYYY-MM-DD in the field, so dated file names, Org timestamps, and properties such as CREATED all work. Matches regex is case-insensitive and may embed variables, as in ^daily/{today}. Asking for “files created today” or “notes from the past 14 days” drafts the same variable-based filters. Apply View previews the new result before Save View persists it. New and Duplicate create separate definitions. Refresh reloads a saved definition and its current source rows.

Click a property cell in either layout, edit the value, choose Preview Change, then Apply to Source. The preview shows the old local value and proposed value. An arrow marks inherited properties; editing them creates an override on the selected note or heading. Empty text creates an explicit empty value. Source links open the exact file and line. Save or cancel an open source editor before making cell edits. A stale source or saved definition fails with a refresh message instead of overwriting newer work. Built-in fields, stable IDs, CELORGA_ runtime metadata and immutable raw/ imports remain read-only here.

Definitions are ordinary JSON files in views/, named by view ID, using celorga:property-view:v1. Copy one into another corpus's views/ directory, keeping its filename matched to its ID, to reuse it there. Views contain relative scope and presentation/query choices, with no private database or machine paths. Rows are derived on Apply/Refresh and after a successful edit; a saved view never copies note bodies. The default builder shows at most 500 rows and indicates truncation. The CLI supports limits up to 5,000 and multiple sort fields. See Tooling reference for the portable schema and automation commands.

Optional apps

Some pages are useful only to some people, so they are optional apps that stay out of the sidebar until you turn them on. Open Settings → Apps, or click Apps… at the bottom of the Workspace section, to see each app with a switch. When the corpus already holds data an app is useful for, the sidebar offers it once, for example “Try People & Companies: your corpus already has 150 people, 210 companies.” Choose Turn On, or Not Now to hide that suggestion on this Mac. The on/off choice is saved in the corpus's celorga.json, so another Mac opening the same corpus shows the same pages.

People & Companies

With People & Companies on, People (Cmd-Option-U) and Companies (Cmd-Option-O) appear below Meetings. They are a lightweight CRM over records you already have: person and company notes (:ORG2_ENTITY_TYPE: person or company), meetings that link or list them, TODOs that belong to them, work-ledger outreach accounts, and your synced calendar.

Each list shows the stage, the company or domain, the next follow-up (red when overdue), and the last touch. Last touch is direct contact: a meeting they attended, a past calendar event with them, or outreach. When someone else only brings them up in a meeting or note, that counts as Last mentioned instead, shown separately in the detail pane and as a dimmed date in the list for entities you have not contacted yet. Lists sort by last touch. Filter by name, email, or domain, and by stage. Companies can show only those with notes, only outreach-only accounts, or both. Select a row to see:

  • Facts: email, role, company, domain, and owner. The pencil edits the property in the note, and the stage menu sets CRM_STAGE.

  • Upcoming: synced calendar events with them in the next 30 days.

  • Follow-ups: open TODOs for the person or company, including those from their meetings and, for a company, from its people. Click the circle to mark one done, or click it to open the source.

  • People: for a company, everyone who works there.

  • Outreach: linked ledger accounts with state, status, and last contact.

  • History: meetings, mentions, closed follow-ups, and outreach events, newest first. Switch between All, Contact, and Mentions.

Follow-up adds a TODO with an optional date, time, and priority to the end of the note, so it appears in Agenda and Calendar. An outreach-only company offers Create Company Note, which creates the note and links the ledger account to it. New creates a person or company note.

The Assist menu has three helpers. Upcoming Meetings briefs the next week's external meetings with each company's stage, last touch, and next follow-up. Plan Follow-ups proposes free slots in the next five working days for due follow-ups, using busy times from your synced calendar; accepting rewrites only each TODO's SCHEDULED line and adds nothing to your calendar. Review Suggested Links lists matches Celorga inferred (an outreach account to a company, a person to a company by email domain, a missing email or domain) and writes the ones you accept as explicit links. Everything is computed by celorga crm, so agents see the same data. Celorga loads the lists and every entity's activity in one read when the corpus opens, so selecting a row is instant. When notes change it refreshes in the background, rebuilding a cached snapshot ahead of time while the pages are closed, and keeps showing the current data until the new data is ready.

Data notebooks and charts

With Celorga, Org documents can connect notes to CSV, Parquet, JSON, ClickHouse, or Metabase data, define SQL views, materialize results, and render charts. Refresh is explicit: opening a note never runs a remote query. Results retain source and freshness information so readers can see where the numbers came from.

Privacy and security

Your corpus is an ordinary folder on your Mac. Celorga does not upload it to a Celorga service. Information leaves the Mac only when you use a destination or source provider you configured, so its retention and data-use policy still applies.

Secrets belong in macOS Keychain or another protected local store. Celorga also supports GPG-backed :crypt: subtrees when individual sections need encrypted storage. When an agent runs celorga secret request, Celorga shows a secure entry sheet with the requester, reason, destination, and recipients, and seals the value with GPG into the corpus secrets file, so it never goes into the chat. Decline records the refusal, and Later keeps the request pending. Consequential external actions can be held for explicit approval before execution.

Back up or sync the corpus with a file-oriented tool you understand, such as Git, Time Machine, iCloud Drive, or Syncthing.

  • Cmd-7, Cmd-8, and Cmd-9 open today's, yesterday's, and tomorrow's daily notes in the document pane. The Daily sidebar links and Choose Date… (Cmd-Shift-7) use the same behavior: they preserve the current first pane, including the selected AI chat and its draft, and do not open the Files list. In Review, Up/Down and Shift-Up/Down also work from the search field: they move into the filtered rows and leave the field, so Cmd-A then selects every filtered item.   • In Search, text results update as you type (two or more characters). Celorga keeps the corpus search index loaded in a background worker from launch, so results arrive in a fraction of a second instead of after loading the index for every query; Return searches a shorter query immediately. Up and Down move through results from the search field, Return opens the highlighted result, and Escape clears the selection, then the query.

  • In Search → This Mac, Return opens the highlighted file in its app (corpus files open in Celorga) and Cmd-Return shows it in Finder.

  • Cmd-R refreshes the workspace when you need a manual reconciliation. Full refreshes of large corpora may take longer than 15 seconds; Celorga lets them continue without reporting a timeout error. Press Cmd-R again or click the stop control to cancel. Actual refresh errors are still reported.

  • Cmd-T opens a tab; Cmd-Shift-[ and Cmd-Shift-] move between tabs.

Full refresh updates the selected document first, then runs up to two independent refresh jobs concurrently. File catalog and assigned-work refreshes stay ordered. Agent-state lists share one CLI request; native assigned-work and similar-TODO scans reuse unchanged file fragments and invalidate them on edits, replacements, or deletions. Timing records for each awaited refresh stage are available through the diagnostics log.

Install and troubleshoot

Download the signed and notarized app from Downloads. Developers who want to build Celorga from source can follow the repository instructions on GitHub.

Celorga checks for signed updates when it opens and every two hours by default. Use Celorga → Check for Updates… to check manually, or the Updates settings to turn automatic checks off and choose whether downloads should install when you quit. Update prompts can also remind you later or skip a version.

Quitting during active chats, recording, or meeting processing asks for confirmation. Celorga makes a best-effort save for up to five seconds after you confirm. A second Quit request (including Cmd-Q or AppleScript) bypasses the pending confirmation or save and exits immediately; unsaved changes or recent output may be lost. If an ordinary quit cannot finish saving, a visible dialog offers Quit or Keep Open; slow saves offer Quit or Keep Waiting. Developer --restart builds send a second quit request after five seconds if needed, and only replace the bundle after the app exits.

For a reproducible launch or refresh problem, use the macOS diagnostics guide. If the app will not open, run celorga doctor --handoff RUNTIME --launch from a terminal to give your chosen agent bounded diagnostic evidence; see agent playbooks. Sanitize diagnostics before sharing them, and never include credentials or private corpus content.

Custom TODO states and action feedback

Open Settings → General → TODO States to edit corpus-wide defaults. Enter space-separated names in the Active states and Terminal states fields. Add independent sequences as needed, then choose Save TODO States. Use Built-in States clears the custom rows; Save applies that choice. Validation errors stay beside the fields, and stale settings require a reload before saving. The settings are portable corpus configuration, shared by the CLI and other clients.

A file can override these defaults. Add a declaration such as #+TODO: TODO MISSED | DONE SKIPPED to a file. States before | remain active; those after it are terminal. Celorga’s heading editor includes the declared keywords, and heading buttons use the configured active/terminal states. Marking a custom state DONE replaces its keyword, preserves the title and ID, and maintains CLOSED metadata.

Workspace errors appear in a dismissible banner on the current surface, with selectable details. Failed actions no longer depend on a hidden status message; successful actions do not open confirmation dialogs.

Experimental Paste as Org

Enable Experimental features in Settings → General. In a document's Source editor (including split view), place the caret or select text, then choose Edit → Paste as Org… (⌘⇧V). Review or edit the Org preview, then choose Insert reviewed Org. Cancel leaves the document unchanged; insertion uses normal editor undo and save behavior. Ordinary paste is unchanged.

Conversion runs locally and only when invoked. Semantic clipboard HTML takes precedence; plain text uses conservative heuristics, with an optional tiny local structure model in the preview. The model is experimental and may mislabel structure. Words and quantities are retained; layout may flatten and uncertain material stays literal. Clipboard content is limited to 200,000 characters per format. No clipboard content is sent to an AI provider. Disabling Experimental features hides the command and prevents insertion from an open preview. The command is currently limited to the Source editor, not rendered inline editors, chat, or code-block bodies.

Live note and heading embeds

Use the document File → Live Embed… menu, or Insert → Live Embed… in the source editor. Search the note list or enter id:STABLE-ID for a note or heading. Insert Embed validates the target through the shared runtime, opens the split editor, and inserts a portable #+EMBED: reference into your draft. Save with the normal editor controls.

#+EMBED: file:../notes/project.org
#+EMBED: id:project-decisions

A file target includes the whole note. An ID target includes the file or heading subtree identified by its :ID: property. Relative file paths resolve from the referencing note; nested references and images resolve from their own source files. The source remains canonical, and corpus file changes refresh the selected rendered document and split preview. Each embed has Open source navigation and a scrollable, read-only content frame; edit the original source to change its content. Embedded headings and tables do not acquire controls that could mutate the host note.

Missing or duplicate IDs, cycles, and limits appear inline. Resolution stays within the active corpus, including after symlink resolution. Nesting stops after four levels, with at most 32 references and 1 MiB of total embedded content per render; a single embed is limited to 256 KiB. ID lookup scans at most 10,000 notes / 64 MiB, honors corpus ignore patterns, and excludes files larger than 4 MiB. For a large source, embed a smaller stable-ID heading or use a normal link.

Exports do not fetch embedded source content. Ordinary HTML exports keep a textual source reference; Export Current Document as PDF keeps the source reference without its live frame. Publish Document replaces embeds with a target-free omission marker in every destination, including web, PDF, and Google Workspace exports. Publish the referenced source separately to review its disclosure. Source .org files preserve the portable directive.

Browser article and selection clipping

Install the source-distributed Chromium extension from this repository's integrations/browser-clip/ directory: open chrome://extensions (or edge://extensions), enable Developer mode, choose Load unpacked, and select that directory. Pin Celorga Web Clipper. There is no store installation or background network service. The extension uses temporary access to the tab you explicitly invoke it on.

  1. Open an HTTP(S) article. Optionally select a passage before clicking the clipper.

  2. Choose Article or Selection, review the extracted text, title and available author, and choose Reading note or Read later task.

  3. Click Save clip and save the portable clip file.

  4. In Celorga, open Capture and choose Import Browser Clip. Choose the file, review its text and metadata, adjust the template if needed, then click Import.

  5. The imported note opens in views/browser-clips.org. Its source URL, author, capture time and hash are in the property drawer; the complete capture envelope is retained under raw/browser/. If you already had an unfinished Capture draft, that window stays open with your text, attachments and settings intact; finish or cancel it to see the imported note underneath.

Article capture prefers a visible article, then visible main, then page text, removing navigation, forms, scripts and content hidden by page CSS or visibility attributes. The preview identifies page-text fallback. It captures currently loaded text, not images, paywall bypasses, PDF viewers or browser-internal pages. Selection capture keeps the selected plain text, trimming surrounding whitespace and normalizing line endings on import; article extraction preserves paragraph boundaries. Content is stored as literal text so source directives cannot execute as Org instructions. Review and promote useful material into canonical notes as an explicit separate action. Duplicate imports of the same clip/template do not append another copy, including after CRLF or drawer formatting changes. Only real heading provenance counts as an import receipt; quoted examples do not suppress capture. A changed source clip or destination requires another preview.

Cancel is unavailable while an import commits. Closing the sheet or changing the corpus or Capture window invalidates pending UI work, so an old operation cannot navigate away from a newer draft. If a source edit starts while import finishes, the clip stays saved without changing the editor; open it from Files after finishing that edit.
